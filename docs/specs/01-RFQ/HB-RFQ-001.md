# RFQ — 요구·인터뷰

## 1. 배경과 동기

은행·카드 거래 내역을 매달 엑셀로 내려받아 손으로 항목(식비·교통·주거 …)을 붙이는 일이 지겹다. 한 달에 200~300건이고, 대부분은 같은 가맹점이 반복된다. 「한 번 정한 것은 다시 묻지 않고, 처음 보는 것만 물어보는」 작은 개인용 도구가 있으면 된다.

- 사용자는 한 사람(나). 팀·공유·다중 사용자는 생각하지 않는다.
- 데이터는 내 컴퓨터 안에만 둔다. 거래 내역을 외부 서비스에 올리고 싶지 않다.

## 2. 명세 체인

이 문서는 HB 프로젝트 11단계 체인의 1단계다. 여기 적힌 것은 사용자(고객)가 말한 요구뿐이며, 판단·설계는 2단계 PRD부터 시작한다. 뒤 단계는 여기의 `Q` 항목을 근거로 참조한다.

## 3. 요구 사항

#### Q1 거래 내역 파일을 그대로 넣고 싶다

은행·카드사 사이트에서 내려받은 CSV 파일을 손대지 않고 그대로 넣으면 읽혀야 한다. 지금 쓰는 곳은 은행 하나, 카드 둘이고 파일 형식(컬럼 이름·날짜 표기)이 서로 다르다.

#### Q2 항목을 자동으로 붙여 달라

거래 한 건마다 항목(식비·교통·주거·통신·의료·문화·쇼핑·이체·수입·기타)을 자동으로 붙여야 한다. 같은 가맹점이면 항상 같은 항목이어야 한다.

#### Q3 틀린 것은 내가 고치고, 다음부터는 기억해라

자동 분류가 틀리면 내가 항목을 바꿀 수 있어야 하고, 같은 가맹점은 다음 달부터 내가 고친 대로 붙어야 한다. 처음 보는 가맹점은 「미분류」로 두고 나에게 물어보면 된다.

#### Q4 한 달 정리를 보고 싶다

월을 고르면 항목별 합계와 그 안의 거래 목록이 보여야 한다. 지난달과 비교되면 좋겠다.

#### Q5 인터넷 없이, 내 컴퓨터에서만

거래 내역이 외부로 나가면 안 된다. 인터넷이 끊겨도 돌아가야 한다. 설치는 복잡하지 않았으면 좋겠다.

#### Q6 같은 파일을 두 번 넣어도 두 배가 되면 안 된다

지난달 파일을 실수로 다시 넣어도 거래가 중복으로 잡히지 않아야 한다.

## 4. 사용자와 환경

| 항목 | 내용 |
|---|---|
| 사용자 | 개발자 본인 1명 |
| 사용 빈도 | 월 1~2회, 한 번에 10분 안팎 |
| 컴퓨터 | 개인 노트북(Windows/WSL 또는 macOS), 브라우저 있음 |
| 입력 | 은행 1곳·카드 2곳의 CSV 다운로드 파일 |
| 규모 | 월 200~300건, 연 3,000~4,000건 |

## 5. 첫 프로젝트

첫 버전에서 되어야 하는 것은 Q1·Q2·Q3·Q4·Q6이다. Q5는 만드는 방식에 대한 제약이다. 「지난달과 비교」(Q4 뒷부분)는 있으면 좋고 없어도 된다.

## 6. 미정

- [ ] 카드사 파일에 「취소」 거래가 별도 행으로 들어오는데 어떻게 처리할지 아직 모른다
- [ ] 현금 지출은 파일이 없다 — 직접 입력이 필요한지 미정
